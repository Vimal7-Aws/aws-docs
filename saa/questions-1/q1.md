## Scenario: Shared NFS Storage for EC2 Instances Across Availability Zones

A company is deploying a fleet of Amazon EC2 instances running Linux across multiple Availability Zones within an AWS Region. The application requires a data storage solution that can be accessed by all of the EC2 instances simultaneously. The solution must be highly scalable and easy to implement. The storage must be mounted using the NFS protocol.

## Solution: Amazon EFS File System

To meet these requirements, we will create an Amazon Elastic File System (EFS) file system and configure mount targets in each Availability Zone where the EC2 instances are running. Then, we will configure the application instances to mount this EFS file system using the NFS protocol.

**Steps:**

1.  **Create an Amazon EFS File System:**
    * Navigate to the Amazon EFS service in the AWS Management Console.
    * Click on "Create file system".
    * Choose the VPC where your EC2 instances are located.
    * Accept the default settings or customize as needed (e.g., performance mode, throughput mode).
    * Click "Create".

2.  **Create Mount Targets in Each Availability Zone:**
    * Once the file system is created, select it and go to the "Mount targets" tab.
    * Click "Create mount target".
    * For each Availability Zone where your EC2 instances reside:
        * Select the VPC.
        * Choose a subnet within that Availability Zone.
        * Select a security group that allows NFS traffic (port 2049) from your EC2 instances.
        * Click "Create".
    * Repeat this process for all relevant Availability Zones. Ensure you have one mount target per Availability Zone for high availability and low latency access from instances within that AZ.

3.  **Configure Security Groups:**
    * Review the security group associated with each mount target.
    * Ensure that the security group allows inbound NFS traffic (port 2049) from the private IP addresses or CIDR blocks of your EC2 instances.
    * Consider adding outbound rules if necessary for your application's communication.

4.  **Mount the EFS File System on EC2 Instances:**
    * Connect to each of your Linux EC2 instances.
    * Install the `nfs-utils` package (or the equivalent for your specific Linux distribution) if it's not already installed:
        ```bash
        # For Amazon Linux / CentOS / RHEL
        sudo yum update -y
        sudo yum install -y nfs-utils

        # For Ubuntu / Debian
        sudo apt update -y
        sudo apt install -y nfs-common
        ```
    * Create a mount point directory on each instance:
        ```bash
        sudo mkdir -p /mnt/data
        ```
    * Mount the EFS file system using the mount target's DNS name. You can find the DNS name in the EFS console under the "Mount targets" tab for your file system. Choose the DNS name corresponding to the mount target in the same Availability Zone as your EC2 instance for optimal performance:
        ```bash
        sudo mount -t nfs4 -o rsize=1048576,wsize=1048576,hard,intr,proto=tcp,port=2049,nolock <mount_target_dns_name>:/ /mnt/data
        ```
        Replace `<mount_target_dns_name>` with the actual DNS name of the mount target in the same AZ. For example: `fs-xxxxxxxx.efs.us-east-1a.amazonaws.com`.

5.  **Persist the Mount (Optional but Recommended):**
    * To ensure the file system is automatically mounted after a reboot, add an entry to the `/etc/fstab` file:
        ```bash
        echo "<mount_target_dns_name>:/ /mnt/data nfs4 defaults,rsize=1048576,wsize=1048576,hard,intr,proto=tcp,port=2049,nolock,_netdev 0 0" | sudo tee -a /etc/fstab
        ```
        Again, replace `<mount_target_dns_name>` with the appropriate DNS name for the AZ.

**Outcome:**

By following these steps, you will have an Amazon EFS file system accessible by all your EC2 instances across multiple Availability Zones using the NFS protocol. EFS provides a highly scalable, elastic, and fully managed file system, simplifying implementation and ensuring data availability and consistency for your application.
